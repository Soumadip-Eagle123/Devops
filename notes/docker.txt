COPY package*.json ./

# 4. RUN the installation command during build
RUN npm install

# 5. Copy the rest of your source code

# 6. Inform Docker about the port

# 7. The command that runs only when the container STARTS

Some description, for better understanding -> 
 1. Daemon → dockerd
 What it is:

The main Docker server process

dockerd
 Role:
Listens to Docker CLI (docker run, docker ps, etc.)
Manages:
images
containers
networks
volumes

 Think:

Brain of Docker

 2. containerd
 What it is:

A container runtime manager

 Extracted from Docker to be a separate component

 Role:
Pull images
Manage container lifecycle
Handle storage
Communicate with low-level runtime (runc)

 Think:

Manager that actually handles containers

 3. shim → containerd-shim
 What it is:

A small intermediate process per container

containerd-shim
 Role:
Keeps container running even if containerd crashes
Handles:
STDIN / STDOUT
exit status

 Think:

Babysitter for each container

 4. runc
 What it is:

Low-level runtime (based on OCI standard)

runc
 Role:
Actually creates the container using:
namespaces
cgroups

 This is where Linux isolation happens

 Think:

The worker that actually builds and runs container
